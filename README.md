# 統合コールセンター管理アプリ｜README（初期設定・操作マニュアル）

このZIPは、**シフト管理・希望休申請・休憩管理をひとつにまとめたWindows向け社内LAN用アプリのソース一式**です。ZIPに完成済みのEXEは入っていません。管理者PCで初回ビルドが必要です。各オペレーターPCへのPythonインストールは不要です。

> **運用上の注意**：本アプリは検証版です。Windows実機・社内ネットワークでの本番運用およびセキュリティ監査は未完了です。Flaskの開発用サーバーを使用し、通信はHTTP（暗号化なし）です。利用開始前に社内IT管理者とセキュリティ・バックアップ方針を確認してください。

## 1. 管理者の初期ログイン情報

| 項目 | 初期値 |
|---|---|
| **管理者ID** | `admin` |
| **初期パスワード** | `Admin123!` |
| 管理者PCのURL | `http://127.0.0.1:5050/login` |
| オペレーターPCのURL | `http://管理者PCのIPv4アドレス:5050/login` |

- 上記ID・パスワードは、**新規にデータベースを作成した場合だけ**有効です。既存データを引き継いだ場合は、以前の管理者パスワードでログインしてください。
- **初回ログイン後すぐ**上部メニューの「パスワード変更」で変更してください。初期パスワードを変更するまでは社内LANへ公開しないでください。
- パスワードは **8〜16文字**、英大文字・英小文字・数字・記号の**4種類のうち3種類以上**を含めます。
- ログイン画面には初期ID・パスワードを表示しません。このREADMEは管理者が適切に保管してください。

## 2. インストールと起動（管理者PC）

1. ZIPを**管理者PC内の書き込み可能なフォルダー**（例：`C:\CallCenterUnified`）に、ファイルをすべて展開します。ZIPの中から直接実行しないでください。
2. インターネットに接続できる状態で、ルートの **`build_windows_no_python_required.bat`** を実行します。必要なポータブルPython、ライブラリ、PyInstallerを取得してEXEを作成します。管理者PCにPythonを事前インストールする必要はありません。初回ビルドではダウンロードが必要です。
3. `dist\CallCenterUnified\CallCenterUnified.exe` が生成されたことを確認します。
4. **`start_built_app.bat`** をダブルクリックするか、`dist\CallCenterUnified\CallCenterUnified.exe` を直接起動します。**起動中のコマンド画面を閉じるとサーバーが停止します。**
5. 管理者PCのブラウザーで `http://127.0.0.1:5050/login` を開き、上記の管理者IDでログインします。
6. オペレーターPCでは、管理者PCのコマンドプロンプトで `ipconfig` を実行して表示されるIPv4アドレスを使い、例として `http://172.16.0.59:5050/login` のようにアクセスします（**このIPは例**で、実際の値に読み替えます）。

- 管理者PCは稼働中、社内LANから到達可能な状態にしてください。Windowsファイアウォールの受信**TCP 5050**は、必要な社内ネットワーク／接続元のみに限定して許可してください。公開インターネットにポートを開けないでください。
- EXEだけをコピーすると起動できない場合があります。別PCへ移すときは `dist\CallCenterUnified` **フォルダー全体**（`_internal` を含む）をコピーしてください。運用上は管理者PCのみでサーバーを起動し、利用者はブラウザーから接続します。
- `start_unified.bat` はPythonを導入済みの環境でのソース起動用です。通常は上記EXE方式を使用してください。`break_engine` の単体サーバーを別途立ち上げる必要はありません。

## 3. 管理者の基本操作（推奨する順序）

1. **従業員**：オペレーターの氏名・ログインID・保有スキル（consumer／merchant／PP）、週最大勤務日数（日曜〜土曜）、月間最大勤務日数（任意）、最大連勤日数、最小／最大勤務時間、早番・中番・遅番の可否を登録・編集します。ログイン画面の新規登録申請はここで承認します。パスワードの再設定や権限変更もここから行います。
2. **勤務パターン**：開始・終了時刻を10分刻みで登録し、休憩時間（分）を設定します。従業員の勤務時間条件との照合は**休憩を含む拘束時間**で行います（例：9:00〜18:00は9時間）。
3. **必要人数**：consumer／merchant／PPの時間帯別最低稼働人数を登録します。
4. **希望休管理**：オペレーターが提出した希望休・午前休・午後休を確認し、承認／却下します。承認された希望休を優先してシフト案を作成します。
5. **月間カレンダー**：対象月を選択し「自動作成」で仮シフトを生成します。登録条件を満たせない場合は警告や診断内容を確認し、従業員条件・勤務パターン・必要人数などを調整します。
6. **日別の配置・休憩案**：日付を開き、保有スキル、必要人数、休憩予定を確認します。複数スキル保持者は勤務中、登録済みの全スキルで受電待機可能な候補として扱います。ただし、1人が複数の通話を同時処理できるとはみなしません。
7. **シフト確定**：「警告・確定」から内容を確認し、必要に応じて理由を記録して最終確定します。確定した勤務日は休憩管理の出勤確認に連動します。
8. **休憩管理**：上部の「休憩管理」→日付の出勤状況・勤務時間・休憩配置案を確認します。必要に応じて「遅刻」「早退」等の理由で**当日の勤務時間だけ**変更できます。休憩案は別途確定が必要です。休憩案確定後、オペレーターの「自分の予定」に反映されます。
9. **シフト出力**：月間カレンダーから確定済みシフトをExcel／CSVに出力できます。個人別または全員分を個別ファイルのZIPとして出力できます。

**月間勤務日数の計算**：月の日数 × 週最大勤務日数 ÷ 7 を四捨五入します（31日・週5日なら22日）。月間最大勤務日数を別途設定した場合は、小さいほうがその月の基準です。週の区切りは**日曜日〜土曜日**です。承認済み希望休・週上限・最大連勤などの条件が競合した際は、無理な勤務を自動で確定しません。

**シフト一括削除**：月間カレンダーの「シフト一括削除」で、選択月の「仮シフトのみ」または「確定済みを含む全件」を指定できます。対象月の再入力と追加確認が必要です。削除前にバックアップしてください。関連する休憩案にも影響します。

## 4. オペレーターの基本操作

1. 管理者からアカウントを案内してもらうか、ログイン画面の「オペレーター新規登録」から申請します。新規登録後は管理者承認が必要です。
2. ログイン後の **「自分のシフト」** には自分の月間シフトだけが表示されます。
3. **「希望休を提出」** では、カレンダーの日付をクリックし、その場で終日・午前休・午後休などを日付ごとに選択し、まとめて申請できます。月間基準勤務日数を下回る可能性がある場合は理由を入力してください。
4. **「休憩管理」→「自分の予定」** では、指定日の勤務時間と休憩の「仮案／確定済み」を確認します。休憩予定が表示されない場合は、日付とシフト確定・休憩案作成の状況を管理者に確認してください。
5. **「パスワード変更」** から各自パスワードを変更できます。

## 5. SQLiteのバックアップ・機種変更・再ビルド

データ保存先は、**EXEのあるフォルダー内**の `dist\CallCenterUnified\data\unified.sqlite3` です。オペレーター・シフト・希望休・休憩管理の共通データを保存します。

- **バックアップ**：全利用者の作業を終了し、EXE（サーバー）を完全に停止します。`unified.sqlite3` を別の安全な場所へコピーしてください。同じフォルダーに `unified.sqlite3-wal` または `unified.sqlite3-shm` がある場合は、そのまま無視してDB単体だけをコピーしないでください。必要ならSQLiteの整合性のあるバックアップ手段を利用してください。
- **同じフォルダーで再ビルド**：ビルドスクリプトには旧 `dist` のデータを一時退避・復元する処理がありますが、**実行前の別途バックアップは必須**です。EXE起動中に再ビルドしないでください。
- **別フォルダーへ移行**：ビルド前後でDBが自動的に引き継がれるとは限りません。停止済みの旧環境から、バックアップ済み `unified.sqlite3` を新環境の上記 `data` フォルダーに移行してください。旧環境と新環境で同時にサーバーを起動しないでください。
- 休憩管理画面の**「復元」操作は統合アプリの入口で制限されており、HTTP 403になる場合があります**。統合SQLite全体の復元は、サーバー停止中のファイル復旧手順で行ってください。旧形式の別DBは、そのまま統合DBへ上書きしないでください。

## 6. トラブルシューティング

| 状況 | 確認すること |
|---|---|
| `ERR_CONNECTION_REFUSED` | EXEが起動したままか／管理者PCの `127.0.0.1:5050` で開けるか／5050番が別アプリに使用されていないか |
| 管理者PCでは開けるが他PCで開けない | IPv4アドレス、同一社内LAN、管理者PCの受信TCP 5050、ファイアウォール設定を確認 |
| `HTTP 500` | EXEをコマンドプロンプトから起動し、表示された `Traceback` を確認。EXEと `_internal` を分離していないか確認 |
| ビルド失敗 | `build_logs\build_latest.log` と `build_logs\build_details.log` を確認 |
| EXE起動失敗 | `dist\CallCenterUnified\runtime_logs\startup_error.log` を確認（作成されている場合） |
| ログインできない | 大文字・小文字、初期パスワード変更の有無、管理者承認、アカウント有効状態を確認 |
| シフト・休憩が表示されない | 対象日、確定状態、勤務状況、休憩案の生成／確定、旧DBからのデータ引き継ぎを確認 |

## 7. 主要ファイル

- `build_windows_no_python_required.bat`：Windows EXE生成（Pythonの事前導入不要、初回ネット接続が必要）
- `start_built_app.bat`：生成したEXEを起動
- `unified.py`：統合サーバーの起動コード
- `shift_planner_app/`：シフト・希望休・従業員管理
- `break_engine/`：休憩・スキル配置管理
- `tests/`：同梱テストコード

**更新時の最重要事項：** `data/unified.sqlite3` を失うと登録データを失います。新しいZIPは実データを含まず、新規状態で起動すると初期アカウントが作られます。旧データを利用する場合は必ず移行してください。


## 従業員の有効化・無効化・編集（統合管理）

- 管理者でログインし、**従業員管理（共通）**（`/employees`）を開きます。ここに有効・無効の両方が表示されます。
- 無効の従業員は「**有効化する**」ボタンで再有効化します。旧休憩管理から取り込んだアカウントは、初回のログイン前に管理者が「パスワード再設定」を実行してください。本人は仮パスワードでログイン後にパスワードを変更します。
- 休憩管理側には有効なオペレーターのみが表示されます。勤務予定がない人は「勤務予定なし」と表示される場合があります。
- 氏名・スキル・勤務条件の編集、新規登録、承認、権限変更もすべて従業員管理に集約しました。休憩管理内の旧編集画面は削除しました。
- 古い休憩管理にしか存在しなかった利用者は起動時に従業員管理へ引き継ぎます。変更前に `data/unified.sqlite3` のバックアップを取得してください。無効化済みの利用者も再有効化でき、過去の休憩・シフトの履歴は保持します。
- 休憩管理の以前のサンプルユーザー（`operator1`～`operator6` かつ表示名が `Operator 1`～`Operator 6`）のうち利用履歴のないものは、誤って実在従業員として追加しないよう除外します。


## 半休希望と早番・中番・遅番の反映（2026-10-12 更新）

- 早番・中番・遅番の複数選択は、登録された各区分の勤務パターンに適用します。勤務パターン画面に**「勤務区分」**を追加しました。既存パターンは従来の「名称から判定」で引き継ぎ、新規／更新では早番・中番・遅番を明示できます。
- **承認済み午前休**：開始が13:00以降の勤務パターンだけが候補。**承認済み午後休**：終了が13:00以前の勤務パターンだけが候補です。両方とも登録した早番・中番・遅番の可否を守ります。
- 半休中でも勤務できるようにするには**該当する半日勤務パターンの登録が必要**です。半休用パターンがなく、その日の勤務候補がない場合に、承認済みの休み時間帯を無視して終日勤務を割り当てることはありません。
- 仮シフト作成では、承認済み希望は必須制約です。**申請中**の希望は優先候補として扱うだけで、確定した休みとは異なります。月間基準勤務日数、週上限、連勤制限が両立しない場合は生成を中止して理由を表示します。
- EXE起動時のSQLite表示は `シフト休憩提案アプリ統合版\dist\CallCenterUnified\data\unified.sqlite3` の短縮表示にしています。**表示の変更だけ**で、実際の保存先は引き続き実行したEXEのあるフォルダーの `data\unified.sqlite3` です。設置フォルダー名を変更しても、この短縮表示は変わりません。

## 従業員管理のキーワード検索（2026-10-12 更新）

管理者の「従業員」画面（`/employees`）にある「登録済み従業員」の上部に、キーワード検索欄を追加しました。氏名・ログインID・保有スキル（consumer／merchant／PP）・有効／無効状態で、入力した文字を含む従業員だけに即時絞り込めます。大文字・小文字・全角／半角の違いは吸収します。スペースで区切った複数のキーワードをすべて満たす人だけが表示されます（例：`田中 merchant`）。「検索をクリア」で一覧を元に戻せます。

検索はブラウザー内の**表示のみ**を変更します。従業員データや有効・無効の状態は変更しません。無効化済みの従業員も検索対象に含み、従来の編集・有効化・パスワード再設定はそのまま利用できます。検索対象は「登録済み従業員」の一覧です（画面上部の共通アカウント承認一覧は対象外）。


## シフト生成と休憩の必要人数判定（2026年10月の検証修正）

- 昼休憩の開始時刻は10分刻みで早番11:30〜13:00、中番13:00〜15:30、遅番15:00〜17:30を候補にします。勤務境界と必要人数を考慮して分散配置し、候補がない場合は警告します。
- 仮シフト生成後、個人の勤務日数・希望休・勤務可能区分を守ったまま、早番・中番・遅番の組み合わせを日別に再評価します。再計算後の休憩込みの不足人数が改善した場合のみ反映します。
- **勤務パターンと契約時間の不一致は自動変更しません。** 初期「早番」09:20〜18:00 は休憩込み8時間40分で、最低9時間の従業員には使用できません。早番を9時間にしたい場合は、勤務パターンを09:20〜18:20などに変更するか、契約に合わせて従業員の時間設定を見直してください。
- 20名いるだけで9:20〜23:00のすべての必要人数を満たせる保証はありません。スキル別の最低人数、週の日数・希望休、休憩、端の時間帯の勤務可能人数次第で不足が残ります。
- 受電待機は複数スキルを同時に選択可能ですが、1人が同時に2件の通話を処理できるとしては計算しません。
- 本修正は月間勤務日の交換を含む厳密最適化ではありません。人員が足りていても不足を完全に消せない場合は、勤務日の入れ替えも含む最適化が必要です。


### 20名による再現検証の設定と結果

このテストは利用者の実際のデータではなく、アプリの生成処理に人工的な20名を登録したものです。

- 対象月：2026年11月（30日）
- 従業員：20名（consumer専任7名、merchant専任7名、PP専任6名）
- 週最大勤務日数：全員5日、最大連勤5日、希望休なし
- 勤務区分：全員が早番・中番・遅番に対応可能
- パターン：早番9:20〜18:00、 中番11:00〜20:00、遅番14:00〜23:00、休憩各60分
- 必要人数：全曜日・全時間帯に各スキル1名（同時着信の実人数も確認）

**旧版**では、従業員の最小・最大勤務時間を9時間にすると早番が全日0件となり、9:20の必要人数が30日すべて不足しました。従業員の許可区分とは無関係に、早番の拘束時間8時間40分が下限9時間を満たさないためです。**新しい版もこの契約条件は変更しません。**

従業員の勤務時間を8〜9時間として早番が利用できる条件にすると、旧版の月間仮シフトは420件生成されましたが、最初の7日間で**84スキル×10分の不足枠**が残りました。新しい版では同条件・同月に420件生成し、最初の7日間の不足枠は**2枠**（5日間は0枠）になりました。重要な差は、昼休憩の候補時刻と、早番・中番・遅番の人数配分を再評価した点です。

なお、これらの結果は**3スキル各1名の必要人数**に対するものです。実際の必要人数がもっと多い場合や、希望休・契約時間が異なる場合は別の結果になります。また、新しい生成はヒューリスティックで、すべての条件で最適解を保証するものではありません。


## 昼休憩を早番から順に分散するルール（最新）

**最新の指定に合わせ、従来の「どの勤務区分も中央3時間」という共通制限は廃止しました。**

| 勤務区分 | 9時間勤務の例 | 昼休憩の開始可能時刻（10分刻み） |
|---|---|---|
| 早番 | 09:20〜18:20 | **11:30〜13:00** |
| 中番 | 11:00〜20:00 | **13:00〜15:30** |
| 遅番 | 14:00〜23:00 | **15:00〜17:30** |

- 上表の時刻は**休憩の開始時刻**です。たとえば早番が13:00に60分休憩を始めれば14:00終了になります。開始時刻だけでなく、勤務時間内に昼休憩を収めることも確認します。
- 昼休憩は早番を11:30〜13:00に配置することを優先し、中番・遅番の候補を後ろへずらします。ただし、実際の開始時刻は各時間帯の必要稼働人数・本人の勤務時間・他者の休憩の重なりを考慮して決定するため、候補が重なる時間帯もあります。
- 通常の休憩順序は **前半10分 → 昼60分 → 後半10分** です。**遅番は「昼60分 → 10分休憩① → 10分休憩②」も許可**します。この場合、管理者・オペレーターの休憩予定表示では「10分休憩①／②」を使います。
- 各休憩の間には20分以上の間隔を取り、同じ人の休憩が重複しないようにします。条件が満たせない場合は休憩を無理に配置せず、警告します。
- 勤務パターンに「勤務区分」が明示されている場合はその設定を優先し、未設定の場合のみ開始時刻を基に早番／中番／遅番を推定します。遅刻・早退時も日付別の勤務時間で再生成します。
- 管理者の手動休憩設定では、昼休憩を選ぶと前半・後半10分休憩の候補が連動して切り替わります。サーバー側でも時間帯と順序を再検証します。
- **既存の確定済み休憩案は自動変更しません。** 新ルールを適用する日は休憩案を再生成し、内容を確認してから確定してください。
